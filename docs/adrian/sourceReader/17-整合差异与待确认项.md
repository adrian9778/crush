## 2. 已按当前源码确认的重点

### 2.1 启动与装配

- `main.go:main` 负责可选 pprof 与 `cmd.Execute`。
- `internal/cmd/root.go` 负责 Cobra 根命令、Workspace 选择和 TUI 启动。
- `internal/app/app.go:New` 构造领域服务、Broker、LSP、MCP 和 Coordinator，
  是单工作区 composition root。

### 2.2 Agent completion 与取消

- `coordinator.run` 以 RunID 关联终态，合并认证重试各 attempt 的 completion，
  最终使用 `PublishMustDeliver` 发布一次。
- `dispatch_cancel_test.go` 固化 cancel-on-entry、多个 accepted run 高水位取消、
  idle cancel 不污染下一次 run、cancel 后新 accepted run 不被误杀。
- `queued_runid_test.go` 固化带 RunID 的排队提示必须作为独立 turn 运行，不能
  静默合并进当前 turn。

### 2.3 Message 持久化

- `message.Service.Update` 对普通文本/推理 delta 做 debounce。
- finish、tool-call 结构变化和 reasoning end 触发同步 flush。
- `Flush`/`FlushAll` 是 Agent completion 和强一致读取的重要边界。

### 2.4 UI

- `internal/ui/AGENTS.md` 明确 `UI` 是唯一 Bubble Tea Model，子组件采用命令式
  方法，由顶层 `Update` 集中路由。
- 布局使用 Ultraviolet screen buffer 与字符串 renderer 的混合管线。
- ANSI 字符串使用 `x/ansi` 处理，Dialog 总宽度包含 border/padding。

## 3. 文档冲突或口径变化

| 主题 | 旧表述差异 | 最终口径 |
|---|---|---|
| 源码规模 | Reader1 约 592 个 Go 文件；Reader3 约 381 个生产 Go 文件 | 区分所有 Go 文件与生产 Go 文件，不混入测试/生成代码 |
| 配置首选 | 早期材料更强调 JSON | `crushrc` 为首选，`crush.json` 兼容且已弃用 |
| 本地/远程 | 简版容易把 App 与 Backend 合并 | App 是单 Workspace；Backend 是多 Workspace 业务层 |
| MCP 初始化 | 容易理解为每次都等待 | 交互 run 不等待；非交互 run 等待初始化稳定 |
| 消息完成 | 可误以为 finish part 足够 | flush 后的 `RunComplete` 是权威 per-run 终态 |
| Broker | 可误以为全部可靠投递 | 普通 Publish 可丢；关键终态和交互请求 must-deliver |

## 4. 待确认与未覆盖运行验证

- Provider 对 reasoning/provider options 的真实线上兼容性。
- OAuth 设备流、token refresh 和 MCP OAuth 的真实超时与错误行为。

- 生产 SLO、告警、备份和回滚策略；仓库未给出统一生产基线。
