### 核心调用序列（逐步逻辑）

1. 从入口包 `main` / `internal/cmd` 定位 composition root `app.New`。
2. 从 `workspace.Workspace` 接口找到 `AppWorkspace` 与 `ClientWorkspace`。
3. 从 `agent.Coordinator` 找到 `*coordinator` 与 `sessionAgent`。
4. 用本索引核对其余包是否都有专题；生成代码只追生成源与消费契约。
5. 未在线验证的外部系统列入第 7 节待确认。

- 文件存在只证明覆盖盘点，不证明运行行为已动态验证。
- `internal/app/testing.go`、`internal/backend/testing.go`、
  `internal/agent/agenttest/` 是测试装配，不是生产入口。
- `internal/ui/logo/example/main.go` 是 logo 示例进程，不是 Crush CLI。
- 同名 `server.go` 出现在 `cmd/`、`server/`、`proto/`，必须用完整路径。

## 2. 入口与装配：关键文件

```text
main.go
  → cmd.Execute
      → fang.Execute(rootCmd)
          → rootCmd.RunE          交互 TUI
          → runCmd.RunE           crush run
          → serverCmd             crush server
          → session/login/models… 其余子命令
      → setupWorkspace
          → setupLocalWorkspace | setupClientServerWorkspace
              → config.Init → db.Connect → skills.Discover → app.New
              → workspace.NewAppWorkspace | NewClientWorkspace
```
